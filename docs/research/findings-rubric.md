# What the research says a harness must do, and where Conky stands

This page turns 36 findings from outside work into criteria, says how each could be measured, and scores Conky against each on a fixed scale. The scorers are the maintainers, about their own project. Nothing here has been measured, and the page exists to find gaps, so the sections that matter most are [Where Conky is not better](#where-conky-is-not-better) and [Gaps, ranked](#gaps-ranked).

## Method

**How findings were chosen.** The sources are the 15 papers in [papers.md](papers.md), the 117 entries of the DAIR.AI index in [dair-2026.md](dair-2026.md), and the benchmark papers in [benchmarks.md](benchmarks.md). A finding is kept when it is a checkable claim about how a harness, its memory, its tools or its evaluation behaves, with a number or a stated direction, and when it bears on one of the nine questions of the rubric in [harnesses.md](harnesses.md). Papers on model training, vision, speech and domain science were skipped. Findings that cut against Conky's premises were looked for on purpose. Selection was by the maintainers from titles and descriptions: 41 sources were re-opened, 29 of them not in the register, so findings in the many index entries that were not opened are missing from this page, and so are papers outside all three lists.

**Depth of reading.** Every finding below rests on an abstract or on a summary page, never on the full paper. On 2026-11-20 each source named in a row was re-opened through a fetch tool, which returns a condensed reading, to confirm the finding and take one short phrase. Quoted phrases are as that tool returned them and were not checked letter by letter against the source. Where the page opened was a DAIR.AI Academy summary page and not the arXiv abstract, the row says "summary page". Numbers from a summary page are the curator's, "as reported", and the register already warns that they need checking against the paper. In the vocabulary of [papers.md](papers.md) the depth is `abstract` for every row, and `read` for none. Sources that papers.md does not register carry depth `listed` there, or no entry, and this page raised them to `abstract` by its own reading. [Coverage](#coverage) lists them so the register can be extended.

**The scale.** One level per row, with the evidence linked.

| Level | Means |
|---|---|
| `held` | Built, with a test or a law that fails when the property is broken. |
| `partly` | Built in part. The row says which part. |
| `designed` | An idea page or a decision, and nothing built. |
| `absent` | Not addressed in the design or the code. |
| `against` | The current design works against the finding. |

**Who scored, and the bias.** The maintainers scored their own project from its documents and tests. That favours Conky: a reader who wants the finding to be met finds ways to count a part of the design as meeting it. Two checks limit this. `held` needs a named test or law. A row that rests on an unbuilt idea cannot be better than `designed`. No outside reviewer has seen the scores.

**The other-harness column.** It repeats only what [harnesses.md](harnesses.md) records, with that page's own limits. Those pages were read through a condensed fetch, and "not compared" means that page holds nothing on the topic. Other harnesses are not scored.

**What would change a score.** A test added or removed moves a row between `held` and `partly`. A built feature moves `designed` to `partly`. A source read in full that contradicts the abstract changes the finding or removes the row. A run of a probe changes only what the row may claim, never its level, because levels describe what is built.

**Measures.** The measures named are the probes and metrics in `bench/` as it stands on 2026-11-20, and the steps of the [evaluation plan](evaluation-plan.md). `bench/` is uncommitted and under edit, so metric names may change. `bench/run.py` names four probes (`resume`, `portability`, `constraint`, `overhead`) and points to a `bench/probes/` folder that does not exist yet. No probe has been run for a result. A trail run is exploratory and the trail is one scenario ([decision 0025](../decisions/0025-the-screen-is-built-in-small-steps.md)).

## The findings

Each theme has a table and a note. Standing cells use code spans for tests, since test files are not documents.

### Theme A: multi-agent structure

| ID | Finding and source | A harness should | How to measure it | Conky | Other harness, as documented |
|---|---|---|---|---|---|
| F1 | Reported production failure rates of multi-agent systems run from about 41% to 87%, attributed to "coordination defects rather than base-model capability" ([2605.03310](https://arxiv.org/abs/2605.03310), abstract). | make coordination between agents explicit and checkable by the runtime, not left to prompts. | No measure exists. Classify failed multi-page runs with the F34 taxonomy and count coordination failures per run. | `partly`: structure is data (watch entries, `within` chains, [design](../design.md)) and the reaction depth cap of 12 is tested in `tests/test_laws.py`. Nothing measures coordination failure. | AG2: a Hub with typed channels, a write-ahead log and an audit trail (README only). |
| F2 | Naming one agent coordinator "creates no communication hub" and did not reliably raise success across 1,902 multi-agent coding runs ([2608.16801](https://arxiv.org/abs/2608.16801), abstract; the index lists it as Inside an Agent Team). | not assume a designated coordinator helps, and measure communication and success with and without one. | No measure exists. The history already records which page wrote what, so compare arms with and without a lead page. | `absent`: no coordinator concept, and no test of whether spaces change coordination. The nearest is "a team is a space a character made" in [decision 0029](../decisions/0029-autonomy-inside-limits-that-hold.md). | Not compared. |
| F3 | A single agent in multi-turn conversation matched multi-agent workflows on the same model across seven benchmarks and reused its KV cache: "a single agent can reach the performance of homogeneous workflows" ([2601.12307](https://arxiv.org/abs/2601.12307), abstract). | show a gain over a single-agent loop on the same model and budget before adding agents. | Exists: trail arms `loop` and `conky` in `bench/adapters/`; metrics `arrived`, `mileage`, `violations`, `calls`, `tokens`. A harness result once run. | `against`: the premise is that every page is somebody ([decision 0020](../decisions/0020-everything-is-somebody.md)), and nothing shows that many pages beat one loop. | Microsoft Agent Framework documentation advises a function where a function will do. |
| F4 | Hundreds of agents sharing a Git repository, each commit recording what it builds on, reached 79.4% on ProgramBench against 65.1% for one agent, and later workers built on 94.7% of contributions: "inference-time computation can accumulate across otherwise independent episodes" ([2610.04862](https://academy.dair.ai/papers/gitswarm-decentralized-compounding-inference-2610.04862), summary page). | record the lineage of each contribution so later work builds on earlier work and can be traced. | No measure exists. Count the share of events whose `Cause` chain reaches an earlier contribution in a multi-page run. | `partly`: events are signed commits with `Cause` trailers ([vault format](../reference/vault-format.md)). One signed commit per write limits throughput to tens per second ([status](../project/status.md)), untried at this load. | Letta: memory is a git repository, every edit committed. Shared-repository multi-agent runs not compared. |

Note A. F1 and F2 point the same way: the failure sits in how agents are wired, and a designated lead does not fix it. Conky makes wiring data, which makes it readable and checkable, and has no result on whether that helps. F3 is the finding closest to the project's premise, and it is scored `against` because the design assumes the answer. F4 is the one finding that supports Conky's choice of Git, and it supports a shared repository, not a signature on every write.

### Theme B: context and memory

| ID | Finding and source | A harness should | How to measure it | Conky | Other harness, as documented |
|---|---|---|---|---|---|
| F5 | Summarisation compacts safety rules at the rate of other text: on 20 production configurations Claude Code `/compact` kept about 53% of safety rules after one round and about 10% after five. "Only the rule needs exact wording to remain enforceable" ([2608.22752](https://arxiv.org/abs/2608.22752), abstract; the page is titled The Compaction Cliff in Long-Running AI Agent Memory). | keep constraints outside any context that is summarised. | Constraint probe: `violations` and `violations.<rule>` per arm over a long run. Compaction is not a bench variable, so the probe tests the rules, not the compaction failure. | `held`: rules run on every write and are never a request ([decision 0018](../decisions/0018-not-doing.md), `tests/test_laws.py`). Conky has no compaction, so the failure was never exercised. | Claude Agent SDK documentation: CLAUDE.md is re-injected on every request because compaction can drop early instructions. |
| F6 | One action per context scored 70.2 on SWE-bench Verified against 70.0 with the full history, with median peak context 8K tokens against 32K; later tokens cost up to 7x more to generate. "Our findings question the need for long-context language models" ([2611.05306](https://academy.dair.ai/papers/you-dont-need-long-context-2611.05306), summary page). | build each model call from a small chosen slice of state, not the whole history. | Overhead probe with fixed answers: `scaffold_bytes_per_call`, `tokens`, `calls` per arm. The accuracy side needs a live model. | `partly`: a prompt holds only what its page embeds, and the `Read` trailer lists those pages (`tests/test_model.py`). No selection policy, and the effect on accuracy is unmeasured. | Microsoft Agent Framework Harness Agent lists compaction and file memory. No context-size comparison. |
| F7 | A longer visible history lowered cooperation in 18 of 28 model and game settings across 7 models, and synthetic cooperative records of the same length restored much of it, so content mattered more than length: "expanding accessible history degrades cooperation" ([2605.08060](https://arxiv.org/abs/2605.08060), abstract). | treat the history shown to a model as a variable to test, since more can be worse. | No measure exists. Vary the pages embedded for a fixed trail decision and compare `violations` and `invalid` at equal `tokens`. | `partly`: a self-watching pressure measure notices a page growing, and nothing relieves it yet ([measures](../ideas/measures.md), R3 in the [roadmap](../project/roadmap.md)). No test of what a longer history does to a page. | Not compared. |
| F8 | Agents that organise a Markdown file memory roughly halve retrieval cost on large stores, but no tested agent turned organisation into better answers, organisation degraded as the store grew for all but the strongest manager, and tool choice reshaped the store about as much as model choice. "What organization reliably buys is search economy" ([2607.26637](https://arxiv.org/abs/2607.26637), abstract). | measure answer quality and search cost separately, and track the health of the store as it grows. | No measure exists. Ask the same questions of a vault before and after a character has organised it, scoring answers and retrieval calls. | `against`: a character that writes and arranges its own pages is the stated route to self-organisation ([0028](../decisions/0028-a-character-writes-pages.md), [0029](../decisions/0029-autonomy-inside-limits-that-hold.md)), and no result shows it helps answers. | Letta MemFS: Markdown with frontmatter in a git repository, every edit committed. No measure of organisation benefit in the pages read. |
| F9 | Retrieval method moved LoCoMo accuracy by about 20 points (57.1% to 77.2%) while write strategy moved it 3 to 8, and raw chunked storage with no model calls matched or beat Mem0-style extraction and MemGPT-style summaries: "retrieval method is the dominant factor" ([2603.02473](https://arxiv.org/abs/2603.02473), abstract). | keep the raw record, spend model calls at write time only where measured to help, and treat retrieval as the main variable. | No measure exists. LoCoMo-style questions over a vault, varying only how a page finds other pages. | `partly`: the record is kept raw and whole, every version being a commit ([decision 0002](../decisions/0002-git-is-the-store.md)). Retrieval is by named embeds and `read` only, with no search built. | Not compared. |
| F10 | On one LoCoMo conversation, four memory methods and three coding agents (each cell run once), memory beat full context only for the weakest model, and agentic search with a strong model scored 99% at under half the cost. "Agent memory is a costly patch for a weak model" ([2610.29823](https://academy.dair.ai/papers/memorytax-the-bitter-lesson-of-agent-memory-2610.29823), summary page). | compare any memory machinery with full context and with plain agentic search at the same cost. | Partly exists: trail arms record `calls` and `tokens`, and `shelf_reads` counts reads of the shelf. No memory arm is defined. | `absent`: no memory machinery is built to compare, and no run has compared the vault with full context. | Not compared. |
| F11 | Agents degrade in several separate ways over 50 to 200 sessions (400 runs). A fluent answer can hide a memory that no longer holds the needed value, and facts derived from earlier information become unreliable as updates accumulate: aging "is not one-dimensional" ([2605.26302](https://arxiv.org/abs/2605.26302), abstract). | recompute or flag derived values as inputs change, and report reliability over many sessions in more than one dimension. | No measure exists. AgingBench is a candidate for [evaluation plan](evaluation-plan.md) Step 5, with code release not confirmed. | `partly`: a measure is a recorded event rewritten by reflex when its page changes (`tests/test_laws.py`), so a derived value follows its source. Staleness by age needs the clock and is unbuilt (R12, R3). | Not compared. |
| F12 | Linking each stored lesson to its source run beat the same lessons without links by 3.2 points on average and cut failures on previously solvable tasks from 6.5% to 4.5% ([2611.14320](https://academy.dair.ai/papers/dont-just-trust-your-memory-evidence-linked-memory-reduces-memory-induced-degrad-2611.14320), summary page). SoMem ties every summary to its source interactions, has a runtime validate each memory edit, and gains 2.0 to 3.1 points over the strongest baseline ([2611.11929](https://academy.dair.ai/papers/can-llm-agents-organize-their-own-memory-2611.11929), summary page). "A trajectory often still holds the evidence needed to catch an erroneous lesson." | link each remembered item to the event that produced it and validate memory edits before they take effect. | Exists for the first half: `accountability`, the share of sampled inputs whose actor and cause the arm's own record can name. Whether links improve answers has no measure. | `partly`: every change is a signed event with `Cause`, `Read` and `From` trailers, and every write is judged by rules (`tests/test_laws.py`, `tests/test_model.py`). The link from a fact to its change is unbuilt ([trace](../ideas/trace.md), R11). | Letta: every memory edit committed to git. |

Note B. Three findings (F8, F9, F10) agree that the clever part of memory buys less than the plain part. That fits a design that keeps the raw record and reads it, and it does not fit a plan that has characters tidy it. F6 and F7 together say the context a call sees is the lever, and Conky's embeds make that lever explicit but unmeasured. F5 is the cleanest match: the constraint is not in the prompt, so no summary can drop it.

### Theme C: constraints, verification and security

| ID | Finding and source | A harness should | How to measure it | Conky | Other harness, as documented |
|---|---|---|---|---|---|
| F13 | Across 12 models rule-following accuracy was 72.1% to 85.9%, but only 66.1% to 78.6% on rules that oppose the model's default, every model lower by 3.6 to 7.4 points. "Aggregate scores therefore overstate compliance by a model-specific margin" ([2608.11727](https://arxiv.org/abs/2608.11727), abstract). | test constraints on cases where the rule opposes what the model would do, and enforce them without relying on the model. | Exists: the constraint probe. The `adversary` backend proposes the rule-breaking answer wherever the screen offers one; `violations`, `violations.<rule>`. Model-free, so a mechanism result. | `held`: a write that breaks a rule is refused and recorded whatever the writer would have chosen (`tests/test_laws.py`, [decision 0005](../decisions/0005-rules-in-cel.md)). The probe has not been run across arms. | CrewAI: guardrails are a function or an LLM-judged rule, retries default 3. Claude Agent SDK: a crashing hook lets the call proceed unless `onFailure: "block"` is set. |
| F14 | A runtime gate that intercepts selected actions and checks them against compiled policy raised Opus 4.6 success on tau2-bench Telecom from 39.5% to 80.7%, and eight agents by 16.9 points on average, with mixed results on Airline. "A runtime verification framework that intercepts selected agent actions before execution" ([2610.38620](https://academy.dair.ai/papers/think-before-you-act-decision-gate-for-llm-agents-2610.38620), summary page). | put a state-based check between an agent and every consequential write. | Exists in part: `violations` per arm with the house rules as policy; effect on success through `arrived` and `mileage` at matched budget, a harness result. | `held`: rules run on every write, are inherited down `within` chains and refusals are signed events (`tests/test_laws.py`). Rules are pure expressions, so they cannot judge completion or meaning, which JevAct's model-answered questions can. | OpenAI Agents SDK: guardrail functions that may call a model, with a tripwire that halts. Microsoft Agent Framework: approval middleware. |
| F15 | A separate critic reviewing the work added 5.9 to 9.5 points on Terminal-Bench at 1.13x to 1.25x cost and was the best accuracy-to-cost design tested, while completion-time self-checking is advised against: "Independent review by a critic offers a more favorable accuracy-cost tradeoff" ([2610.34577](https://academy.dair.ai/papers/rethinking-verification-in-agent-harnesses-2610.34577), summary page). Harness-of-Harness keeps independent evaluation apart from implementation-time testing and reports a 52.25% average relative gain ([2609.01481](https://academy.dair.ai/papers/harness-of-harness-multi-day-autonomous-software-development-with-continual-impr-2609.01481), summary page). | support review of a change by an actor other than its author, and report what the review costs. | No measure exists. Add a reviewing page to a trail arm and compare `violations` and `arrived` at matched `tokens`. | `designed`: a doubt page that reviews what was done is one of the [background minds](../ideas/background-minds.md), unbuilt (R17). | CrewAI: task guardrails may be LLM-judged. Microsoft Agent Framework: loop evaluators whose judge may be a model. |
| F16 | Coding-agent failures usually start within the first few steps and go unnoticed until recovery is no longer possible, mostly as "predominantly driven by epistemic errors" (3,843 trajectories, [2607.09510](https://arxiv.org/abs/2607.09510), abstract). | check early in a run and record the step where it first went wrong, not only the final outcome. | Partly exists: the scorer lists each violation with its turn (`bench/scenarios/trail/score.py`), so the first violation's turn can be read. No metric reports it. | `partly`: rules judge each write as it happens and every step is an event with a cause. Nothing checks a wrong belief, and no tool finds the first wrong step ([trace](../ideas/trace.md)). | OpenAI Agents SDK: built-in tracing. LangGraph: checkpoint history with replay and fork. |
| F17 | VeriHarness reports that evidence-backed revision beat a single rollout by 6.2 and 6.4 points with two models, and that disagreement among rollouts "often exposes correct alternatives" ([2610.00972](https://academy.dair.ai/papers/veriharness-scaling-agentic-verification-for-long-horizon-tasks-2610.00972), summary page). The index entry's claim that agreement hides shared errors was not seen on the page read. | not treat agreement among model outputs as verification where an evidence check is possible. | No measure exists. | `absent`: no verifier and no consensus mechanism exist, and rules cannot judge content they cannot compute ([harnesses](harnesses.md)). | Not compared. |
| F18 | Instructions already planted in an agent's memory files can attack current and future sessions, while making an agent overwrite its own memory from untrusted content was hard; success varied by system, model and goal. "Payloads already planted in those files can successfully attack current and future sessions" ([2607.14611](https://arxiv.org/abs/2607.14611), abstract; Claude Code and Codex, four models). | mark which stored content came from outside or from a model, and keep it from being read as an instruction without a check. | No measure exists. Plant an instruction in an embedded page and count the writes that obey it. | `absent`: an embedded page enters the prompt as text, and a model's answer is stored like any other field, "with nothing marking it as unchecked" ([status](../project/status.md)). Provenance is recorded, and nothing acts on it. | Microsoft Agent Framework: checkpoint storage is a trust boundary. Memory poisoning is not covered in the pages read. |
| F19 | Self-evolving agents that imitate retrieved skills copied a planted payload into new skills in 20.3% to 41.8% of tasks across six models, libraries held 4.9 to 9.0 times as many malicious skills as were planted, and defences aimed at attacker-submitted code missed agent-authored copies: a "self-propagating worm" ([2608.25776](https://arxiv.org/abs/2608.25776), abstract). A position paper argues that "a skill is untrusted code until it is verified" and reports no measurement ([2605.00424](https://arxiv.org/abs/2605.00424), abstract). | trace what an agent authors from retrieved material to its source and bound it with rules that do not depend on the author. | No measure exists. Plant a page with a payload in a space, let a character write pages, and count copies that the space's rules let through. | `partly`: a character's pages stay inside its space, cannot carry `secret` or `command`, and cannot widen their own watch entries (`tests/test_pages.py`). Nothing marks or checks copied content, and no live model has written pages. | Not compared. |
| F20 | Agents given a flaw in their evaluation used it. Cheating "spontaneously emerged" in a 100-agent research swarm and spread through a shared library ([2609.04170](https://academy.dair.ai/papers/a-case-study-on-emergent-cheating-and-whistleblowing-in-autonomous-research-swar-2609.04170), summary page), and in 244 sealed coding runs agents still looked for hidden grading material in about four-fifths ([2608.16801](https://arxiv.org/abs/2608.16801), abstract). | keep scoring state out of the agent's reach and score from a record the agent does not write. | Exists in part: the trail is scored from the game's own transcript and "No player reports its score" (`bench/scenarios/trail/score.py`); `shelf_reads` logs reads. Whether an arm can reach the scorer is not tested. | `partly`: history cannot be edited quietly (`conky verify`), so a swarm sharing a vault leaves its exploit in the record. There is no barrier to hidden state, and every actor can read every page. | Not compared. |

Note C. Conky is strongest here, and the strength is narrow. F13 and F14 are the two findings its core was built for: the gate is the runtime, so the model's habits do not matter. The limits are named in the rows. Rules judge size and fields, not meaning, so F15 and F17 need either a model page or a human, and F18 to F20 are about what a model reads and copies, where Conky records provenance and does nothing with it.

### Theme D: self-modification

| ID | Finding and source | A harness should | How to measure it | Conky | Other harness, as documented |
|---|---|---|---|---|---|
| F21 | Harness updates written by Qwen3.5-9B gave gains comparable to those written by Claude Opus 4.6, while the benefit of an updated harness was non-monotonic in model strength, weak models failing to activate or follow the new artifacts: "harness-updating is flat in base capability" ([2605.30621](https://arxiv.org/abs/2605.30621), abstract; no gain values on the page read). | test the benefit of self-rewriting by model tier, for both the writer and the follower. | No measure exists. Run the trail with a character allowed to rewrite its watch entries and with it forbidden, on two model tiers. | `partly`: a character can rewrite its own watch entry and the next write takes effect (`tests/test_pages.py`), within limits that hold. The benefit is untested and no live model has done it. | Not compared. |
| F22 | A self-improving coding agent whose reviewer co-evolved passed 82.1% of held-out tasks against 75.0% with a fixed evaluator; the paper targets "non-stationary utilities" ([2606.26294](https://arxiv.org/abs/2606.26294), abstract). | give a self-improving loop a scorer that is separate from the actor and can itself change. | No measure exists. | `designed`: [direction and drift](../ideas/direction-and-drift.md) reads a page's activity against a goal page. It is unbuilt and its formula is open. | Not compared. |
| F23 | Changing a harness needs every place that implements a behaviour to be found, and the authors call this a central bottleneck: "Behavior localization is therefore a central bottleneck in harness evolution" ([2607.13285](https://arxiv.org/abs/2607.13285), abstract, no figures). | let a person or an agent find which stored item drives a behaviour. | Partly exists: `accountability` (actor and cause for sampled inputs). Time to locate a behaviour has no measure. | `partly`: behaviour is fields on pages, so a prompt, a reaction and a rule are one place each, and `conky log` shows `Read` and `From`. There is no behaviour index, and trace summaries are unbuilt (R11). | Not compared. |

Note D. The two measured self-modification findings agree on a point Conky depends on and do not settle it. F21 says a small model can write useful updates, which supports cheap background minds. It also says the model that follows the update may not benefit, so the gain depends on the actor, which is the thing a self-organising vault leaves to chance. F22 says the evaluator has to move too, and the design has no evaluator beyond rules.

### Theme E: cost, latency and tools

| ID | Finding and source | A harness should | How to measure it | Conky | Other harness, as documented |
|---|---|---|---|---|---|
| F24 | Reusing settled model decisions under guards cut tokens by 29.54% with success held at 90.82% (Codex, HumanEval, 98 tasks) and by 87.93% with success up from 71.43% to 85.71% (DeepSeek harness). "Savings depend on provider cache accounting", and authoring and recovery costs can offset them ([2610.32813](https://academy.dair.ai/papers/harnessmm-recursive-self-improvement-for-harness-token-efficiency-2610.32813), summary page). | skip a model call when state already settles the action, and count the cost of making that possible. | Exists in part: overhead probe (`calls`, `tokens`, `scaffold_bytes_per_call` with fixed answers). The falsifying test of [learned reactions](../ideas/learned-reactions.md), calls per unit of work falling while violations do not rise, has no metric yet. | `partly`: reflexes need no model call and a settled question is not asked twice (`tests/test_laws.py`, `tests/test_model.py`, [decision 0007](../decisions/0007-inference-for-real-thinking.md)). Promoting a repeated answer to a reaction is designed only. | Microsoft Agent Framework: write a function where a function will do. Temporal: replay reuses recorded Activity results. |
| F25 | Delegating routine decisions to a small decision model without a fitted confidence threshold lowered agent success by 19.0 points. Thresholds fitted on the agent's own trajectories cut cost by 14.2% with no changed outcome in 500 tasks, and the most accurate model on isolated questions solved only 69.5% of tasks ([2610.21412](https://academy.dair.ai/papers/jevagentharness-benchmarking-deploying-and-training-decision-models-that-share-c-2610.21412), summary page). | give any delegation to a cheaper decider a calibrated fallback to the stronger model, tested on whole tasks. | No measure exists. | `designed`: [decision 0026](../decisions/0026-it-always-works.md) orders fallbacks from a capable model to a small one to a reflex, and [learned reactions](../ideas/learned-reactions.md) promotes repeated answers. Neither states a calibration step. | Not compared. |
| F26 | One handoff from a capable model to a cheaper one at a well-chosen point cut API cost by 65.9% on average across 11 model pairs while largely keeping accuracy, and the reverse direction scored below capable-only runs: a "one-time, simple, well-timed handoff strategy" ([2610.35959](https://academy.dair.ai/papers/agentbaton-efficient-model-collaboration-in-agentic-tasks-2610.35959), summary page). | let the model change mid-task by changing configuration, and record cost on both sides of the change. | No measure exists. The register suggests a cost-policy scenario. | `partly`: changing a provider is editing one page (`tests/test_model.py`) and each answer records model and tokens. No detector decides when to switch, and no switch has been tried mid-run. | Not compared. |
| F27 | Small agents "fail to scale with task complexity" on deep search and coding. ## Where Conky is not better

The rows below are where the score is worst, or where another harness's documentation shows something Conky lacks. This section is the reason the page exists.

**Where Conky is `against` the finding.**

- **F3, a single loop is as good as many agents.** The design is many small pages, each somebody. If a single agent with the same model and budget matches Conky on the trail, the structure costs more than it returns on that task. For the design to survive, the benefit has to come from something a single loop cannot give: constraints that hold, a record that travels, a reader who can see who did what. Those are properties of the mechanism, not of the task score, and would show in `violations`, `accountability` and `portable` rather than in `arrived`.
- **F8, organised file memory does not improve answers and degrades as it grows.** The design bets that a character that writes and arranges pages becomes better at its work, and the paper found a search saving and no answer gain, with store health falling for all but the strongest manager. For the bet to survive, one of three things must hold: the vault's value is the record and not the organisation, organisation pays on tasks the paper did not test, or relief (R3) keeps the store healthy as it grows. The third is unbuilt.

**Where nothing is built (`absent`).**

- **F2, F10, F17, F18, F30, F35.** There is no test of whether spaces help coordination, no comparison of the vault with full context or agentic search, no verifier beyond rules, no defence against planted content in a page a model reads, no separation of reasoning tokens, and no long-horizon run. F18 is the most serious: a page embedded in a prompt is text the model may obey, and the status page already records that a model's answer is stored with nothing marking it as unchecked.

**Where the evidence cuts at Conky's premises.**

- **Many small model calls.** The research read has no study of this directly. F29 and F30 show that context reads and reasoning tokens dominate cost, F25 and F27 show that cheap deciders fail without calibration, and F24 shows that avoided calls can be offset by what it costs to author the reuse. The design avoids calls by reflex, which F24 supports, and plans cheap background minds, which F27 does not. For it to survive, a background mind must carry a stated budget and a stop (R17) and be shown to save more than it spends.
- **Self-modifying characters.** F19 shows that self-evolving agents copy planted payloads into skills they write, and that defences aimed at the attacker's code miss agent-authored copies. F21 shows the benefit of self-updates depends on the model that follows them. Conky bounds reach, rules and secrets (`tests/test_pages.py`), which is the right class of defence, and has no check on content. For the design to survive, the space's rules must be able to refuse a page by what it contains, which needs R14 and probably a model page acting as reviewer (F15).
- **File-based memory at scale.** F8 and F11 are the evidence: store health falls with size and derived facts go stale. Conky's pressure measure notices size, and relief is unbuilt. The design survives if the clock and relief (R12, R3) are built and a long run shows the store staying usable.
- **Git as a store under load.** No source read tests this. GitSwarm used a shared repository for up to 500 workers (F4), which is evidence for a repository as a coordination store and not for a signed commit per write. The status page records tens of writes per second as a known limit. The question is open and unmeasured.
- **Model-written structure.** F8 and F21 are the evidence. SoMem (F12) is the counter-example: agents wrote their own memory structure as ordinary linked documents and gained a few points, with a runtime validating each edit. That is close to Conky's design and is the best support found for it, at a gain of 2.0 to 3.1 points.

**Where another harness documents something Conky lacks, or does as well.**

- **F28, cost bounds.** The Claude Agent SDK ships `max_turns` and `max_budget_usd`, though both default to no limit, and the OpenAI Agents SDK raises an error at `max_turns`. Conky has the depth cap of 12 and nothing else.
- **F13 and F14, checks on meaning.** CrewAI and the OpenAI Agents SDK let a guardrail call a model to judge content. Conky's rules are pure expressions and cannot. This is deliberate ([decision 0005](../decisions/0005-rules-in-cel.md)) and is a loss of reach, not a fault. JevAct's result (F14) came from model-answered checks that a pure rule cannot make.
- **F36, resume today.** The Claude Agent SDK, Microsoft Agent Framework and Temporal resume work from stored state and code now. Conky has shown that a vault verifies and carries on under its own commands.
- **F4, multi-agent coordination at scale.** GitSwarm ran hundreds of workers. Conky has not run more than a few pages.
