# 1. Product Requirements Document (PRD): SunnySide Autonomous Mesh

## 1.1 Executive Summary & Vision

SunnySide Autonomous Mesh is a reference implementation of a zero-orchestration autonomous business running on The Living Mesh architecture atop Astrid OS (astrid-runtime/astrid) and Wasmtime. Rather than hardcoding workflow scripts, prompts-as-security, or bloated chat logs, every actor in the business—LLM strategist, double-entry accounting engine, chat archive, physical pitcher sensor, customer kiosk, and human owner—runs as an isolated WebAssembly Capsule with zero ambient authority. `[source label: GitHub]`

All actors interact through 4 primitives (crest, surface, anchor, seal) and 3 verbs (peek, watch, etch), projecting a bounded (≤4KB) present-tense Markdown cockpit above the waterline while storing deep operational history below it.

## 1.2 Hypervisor & Node VM Selection: Astrid OS + Wasmtime

**Node VM Engine — Wasmtime (bytecodealliance/wasmtime):** Selected as the underlying execution hypervisor for its Bytecode Alliance standards compliance, Cranelift JIT/AOT compilation, deterministic WASM fuel metering, sub-millisecond capsule instantiation, and WebAssembly Component Model (WIT) sandboxing. `[source label: GitHub]`

**Micro-OS Kernel — Astrid Runtime (astrid-runtime/astrid):** Selected as the capability-secure agent operating system wrapping Wasmtime. Astrid provides a "dumb" Rust kernel (`astrid-daemon`) that enforces ed25519 cryptographic capability grants, routes typed IPC messages, mounts content-addressed durable volumes via Linux FUSE / macOS FSKit (`astrid.volume`), bridges external hardware/APIs via hash-verified MCP servers (`astrid-mcp`), and maintains a tamper-evident BLAKE3 hash-linked audit chain. `[source labels: GitHub, + 1]`

## 2.2 Canonical WIT Interface Contract (`contracts/living-mesh.wit`)

All capsules compile against this WebAssembly Interface Types (WIT) contract via `astrid-build`: `[source label: Docs.rs]`

```wit
package sunnyside:mesh@0.1.0;

interface types {
  type crest = string;     // e.g. "@a19f4c881b"
  type anchor = string;    // e.g. "@ledger#cash_usd"
  type seal-sig = string;  // e.g. "sig:ed25519:..."

  record journal-line {
    account: string,
    unit: string,          // "USD" | "OZ" | "LB" | "CPU"
    delta: float64,
  }

  record etch-request {
    target: anchor,
    patch-json: string,
    conserve: list<journal-line>, // Must sum to 0 per unit if non-empty
    shadow: bool,                 // True = simulate in-memory, zero commit
    purpose: anchor,              // OTel span & cost attribution tag
    witness-seals: list<seal-sig>,
  }

  variant mesh-error {
    viewport-overflow(u32),   // Violates 4096-byte surface law
    ward-blocked(string),     // Blocked by inherited invariant
    quorum-pending(anchor),   // Returns URI of generated quorum gate
    conservation-imbalance,   // Debits != Credits
    unauthorized-capability,
  }
}

interface airlock {
  use types.{anchor, etch-request, seal-sig, mesh-error};

  peek: func(target: anchor) -> result<string, mesh-error>;
  watch: func(target: anchor, when-expr: string) -> result<u64, mesh-error>;
  etch: func(req: etch-request) -> result<seal-sig, mesh-error>;
}

world iceberg-capsule {
  import airlock;
  export on-breath: func(trigger-anchor: anchor, payload-json: string) -> result<string, string>;
}
```

# Product Requirements, Technical Specification & Meta-Benchmark

## 1. Executive Summary & Vision

Traditional agent frameworks rely on brittle orchestration, bloated chat logs, and static tool-calling loops. The Living Mesh replaces orchestration with computational physics. It separates the domain-agnostic execution kernel (`conky`) from the application and benchmarking bundle (`SunnySide`).

- **conky (The Ambient Reality Kernel):** A lightweight, transparent hypervisor (built on Astrid OS and Wasmtime) where every entity is an isolated WebAssembly capsule. - **SunnySide (The Meta-Benchmark):** An autonomous enterprise experiment simulating a lemonade stand. It serves as a testing ground where a single seed prompt given to an agent evaluates its ability to autonomously discover resources, synthesize custom tools, run verifiable experiments, and optimize its own inference spend.

To eliminate ceremony, conky enforces a strict ontology of single-word identifiers across its WIT schemas, GraphQL overlay, and YAML physics.

### 2.1 The Four Irreducible Primitives

- **crest:** Self-certifying ed25519 cryptographic identity (`@a19f4c...`). Every node's address is the hash of its public key.
- **surface:** A bounded (≤4KB) present-tense Markdown document. YAML frontmatter defines strict physics (`ward`, `gate`); the prose body defines semantic reality.
- **anchor:** A live URI pointer (`@crest#path`) linking surfaces, transcluding external state inline, or delegating inherited norms.
- **seal:** A cryptographic signature (ed25519 over `blake3(delta + base + anchor)`) emitted on every state mutation, establishing an immutable causal DAG.

### 2.2 The Three Protocol Verbs

- **peek(@anchor):** Lazy, permission-checked read. Resolves remote data into local context or queries a deep domain node.
- **watch(@anchor, when):** Reactive subscription linked to an asynchronous Completion Port. Nodes sleep at zero compute until the `when` condition holds.
- **etch(@anchor, patch, seal):** Atomic mutation of a surface. Evaluated deterministically against all inherited constraints.

### 2.3 Ecological & Cognitive Fields

Instead of simulating psychological states with complex prompts, conky natively computes scalar field gradients that influence agent behavior before inference begins.

- **aura:** Radiated by nodes into the mesh (e.g., a weather oracle radiates heat, a busy chat radiates bustle).
- **drive:** The homeostatic pressure felt by an agent (strain, urgency, novelty).
- **focus:** The dynamic product of `aura` and `drive`. High focus narrows the agent's attention to foveal `watch` triggers; low focus broadens peripheral curiosity, triggering `peek` explorations of ambient @anchors.

## 3. The Universal WAL & Iceberg Architecture

Every node in conky is an Iceberg. The `surface` is just the visible ≤4KB tip.

### Deep Domain Engines

- **mind:** Probabilistic LLM.
- **gear:** Deterministic WASM, CEL rules, or state machines.
- **organ:** Hardware bridges or SQLite-backed deep stores.
- **voice:** Human UI projectors.

### The Universal WAL (`@wal`) & `parity`

To survive concurrent asynchronous operations without robotic lock-stepping, all mutations flow through a central Write-Ahead Log utilizing Completion Ports.

- **parity (Double-Entry Conservation):** Any `etch` moving scarce units (`usd`, `oz`, `cpu`) must balance to zero.
- If `@standkeeper` initiates a barter, it submits an incomplete entry to `@wal` with `parity: provisional`. The Completion Port suspends execution until the counterparty signs a `seal` that zeroes the balance.

## 4. Autopoietic Tool Synthesis (`@forge`)

True autonomy requires the ability to manufacture new tools and infrastructure dynamically. conky provides `@forge`, a factory engine allowing `mind` cells to compile and spawn custom `gear` and `organ` nodes to optimize their own operations.

### Example: SunnySide Tool Generation

When `@standkeeper` realizes it is burning excessive `$cpu` doing manual inventory math during high heat `aura`:

1. It calls `etch(@forge/mint, { engine: "gear", source: "cel:..." })`.
2. `@forge` compiles the script into a new WASM capsule (`@batch-scaler`).
3. The new node inherits an attenuated `pass` (capability token) from `@standkeeper` and acts as a zero-cost deterministic tool for all future batch calculations.

## 5. Technical Design: Astrid OS & `conky.wit`

conky runs on Astrid OS, utilizing Wasmtime for execution, FUSE/FSKit for surface file mounting, and WASM Component Model (WIT) for sandboxing.

```wit
package conky:kernel@1.0.0;

interface types {
  type crest = string;
  type anchor = string;
  type seal = string;

  record line {
    vault: string,
    unit: string,    // "usd" | "oz" | "cpu"
    shift: float64,
  }

  record patch {
    target: anchor,
    delta: string,
    parity: list<line>, // Must sum to 0
    shadow: bool,       // Counterfactual dry-run flag
    base: seal,         // Optimistic concurrency check
  }

  variant fault {
    sprawl(u32),   // 4KB boundary violation
    ward(string),  // Blocked by physics invariant
    gate(anchor),  // Pending multi-signature quorum
    imbalance,     // Parity != 0
    taint,         // Airlock prompt-injection block
  }
}

interface airlock {
  use types.{anchor, patch, seal, fault};

  peek: func(target: anchor) -> result<string, fault>;
  watch: func(target: anchor, when: string) -> result<u64, fault>;
  etch: func(req: patch) -> result<seal, fault>;
}
```

## 7. Adversarial Review & Hardening

To ensure the mesh does not collapse under its own agency, structural defenses are built into `conky-airlock`:

- **Tool Sprawl (`fault::sprawl`):** Unchecked autopoiesis crashes memory. `@forge` enforces canonical BLAKE3 deduplication (preventing duplicate scripts) and hard realm limits on active child nodes.
- **Stalled Escrow Griefing:** A pending `parity: provisional` transaction locks state. All incomplete `wal` entries require a `ttl` (Time-To-Live). If unmet, conky automatically rolls back the `base` seal.
- **Peripheral Prompt Injection (`fault::taint`):** External beacons could inject malicious instructions. The airlock applies taint-tracking to `peek` responses; any data sourced from untrusted `crest` zones is cryptographically fenced from triggering `pass` capability grants.
- **Amnesia via Elastic Folding:** Vital operational context could be compressed away. Nodes can declare `pin: true` on critical surface blocks, forcing the airlock to retain them in high-resolution active memory regardless of token pressure.
