## 1. Core Philosophy: The Document Is the System

conky is a domain-agnostic ambient reality kernel built on Astrid OS (astrid-runtime/astrid) and Wasmtime. SunnySide is an autonomous enterprise experiment and meta-benchmark—a self-organizing lemonade stand—hot-mounted onto conky to evaluate autonomous agency. `[source label: GitHub]`

Unlike traditional runtimes that scatter state across `.toml` manifests, configuration registries, environment variables, database schemas, and hidden lockfiles, conky enforces total document transparency:

- **Zero Config Registries or External State Files:** There are no `.toml` distro files, no central routing tables, and no hidden metadata stores. The entire mesh is a directory of living Markdown `surface` documents (≤4KB each) mounted via Astrid OS's FUSE / FSKit volume layer.
- **Directly Viewable & Editable:** Every entity—an LLM agent, a realm's governance rules, a capability `pass`, a forged tool's source logic, a ledger viewport, or a harness adapter—is a live `.md` surface. A human opening a file in any editor or an agent calling `etch` sees and mutates the exact same canonical reality.
- **The Iceberg Boundary:** While everything shared lives above the waterline as a ≤4KB living Markdown surface, high-volume historical data (SQLite double-entry journals, millions of chat messages, cold causal traces) lives strictly private inside individual WebAssembly capsules below the waterline—accessible only through their surface viewports.

### 3.2 Universal Write-Ahead Log & Completion Ports (`@wal`)

Rather than rigid step-by-step workflows, all state transitions submit into `@wal` (`engine: organ/wal`), modeled on `io_uring` Completion Ports and double-entry accounting:

- **Zero-Sum Conservation (`parity`):** Any `etch` moving scarce units (`usd`, `oz`, `lb`, `cpu`) must balance to zero (`∑ shift == 0` per unit) across vaults without breaching a `ward` floor.
- **Provisional Escrows (`ttl`):** For asynchronous multi-party actions (e.g., bartering lemons for ice with a neighboring cart), a node submits a provisional entry. Its Completion Port suspends execution until the counterparty signs a balancing `seal` before `ttl` expires—or automatically rolls back to `base`.
- **Automatic Inference Metering:** Every `mind` breath pre-projects token cost against `@wal#cpu` before inference and posts a balanced `cpu` debit on `exhale`, tagging the seal with the active `purpose` @anchor for end-to-end OpenTelemetry tracing.

### 3.3 Canonical WIT Contract (`conky.wit`)

All Wasmtime capsules compile against a single WebAssembly Component Model interface:

```wit
package conky:kernel@1.0.0;

interface types {
  type crest = string;
  type anchor = string;
  type seal = string;

  record line {
    vault: string,
    unit: string,         // "usd" | "oz" | "lb" | "cpu"
    shift: float64,
  }

  record patch {
    target: anchor,
    delta: string,
    parity: list<line>,   // Must sum to 0 per unit if non-empty
    shadow: bool,         // True = counterfactual dry-run, zero commit
    purpose: anchor,      // OTel trace & cost attribution anchor
    base: seal,           // Optimistic concurrency parent seal
  }

  variant fault {
    sprawl(u32),          // Exceeds 4096-byte surface limit
    ward(string),         // Blocked by inherited frontmatter invariant
    gate(anchor),         // Blocked awaiting multi-crest quorum signatures
    imbalance,            // Double-entry parity != 0
    taint,                // Blocked untrusted peripheral injection
  }
}

interface airlock {
  use types.{anchor, patch, seal, fault};

  peek: func(target: anchor) -> result<string, fault>;
  watch: func(target: anchor, when: string) -> result<u64, fault>;
  etch: func(req: patch) -> result<seal, fault>;
}

world capsule {
  import airlock;
  export breathe: func(trigger: anchor, payload: string) -> result<string, string>;
}
```

## 2. Mandatory Provable Validator Ports (`guard`)

### 2.1 Why Validators Must Be Formally Provable

In an autopoietic mesh where `mind` agents (`@standkeeper`) synthesize new tools (`@forge`), edit DuckDB notebooks, and evolve prompts, an unverified validator introduces fatal failure modes:

- **Non-Termination (Commit DoS):** An infinite loop in a custom validator freezes the pre-commit pipeline.
- **Non-Determinism (Replay Divergence):** A validator reading wall-clock time or network state passes during `shadow: true` dry-runs and fails on actual commit.
- **Invariant Erosion (Privilege Escalation):** An agent alters a child document's validator to bypass `@realm` spending caps or double-entry parity rules.

conky-airlock eliminates all three structurally. Every document in the vault must declare `guard: "[[guard-<crest>]]"` in its frontmatter. Any document lacking a valid guard pointer—or referencing a guard without a valid `proof` certificate—is quarantined in `fault::unproven` and cannot accept `etch` mutations.

### 2.2 The Two-Stage Provability Pipeline

Whenever a `guard-*.md` document is created or modified (by a human in Obsidian or an agent via `@forge`), conky-airlock runs a deterministic verification pipeline before issuing its `proof` certificate:

**Stage 1 — Static Purity & Totality Verification (Wasm Component Analysis):**

The validator's `code:` block (written in pure CEL or compiled Rust/Wasm) is inspected at the Wasm bytecode level.

- **Zero-Effect Import Check:** The Wasm module is rejected if it imports any host function other than pure `peek-snapshot` (read-only access to `pre`, `post`, `realm`, and `wal` delta). No clocks, RNG, I/O, or `etch` imports exist in the `guard-world` WIT boundary.
- **Bounded Fuel / Loop Totality Check:** Backward branches and recursion are statically bounded (or compiled from loop-free CEL), proving worst-case execution completes within `fuel <= 10_000` (≤0.4ms).

**Stage 2 — Symbolic Subsumption Proof (SMT Invariant Preservation):**

conky-airlock translates both the inherited `@realm` `ward` predicates and the candidate `guard` predicate into first-order logic formulas over frontmatter variables and `wal` deltas, then invokes an embedded SMT solver (`oxiz` / `z3` Wasm capsule) to prove:

```
¬∃ s ∈ State : ( Guard_doc(s) ∧ ¬Ward_realm(s) )
```

- If a counterexample state `s` exists where the validator accepts a mutation that `@realm` forbids, verification fails with `fault::weakened(counterexample)` and refuses to sign the guard.
- If unsatisfiable (proven sound), conky-airlock stamps `proof: "cert:smt:<blake3(wasm + realm_seal)>"` onto `guard-<crest>.md`.

### 2.3 Pre-Commit Execution Flow

Every state transition—whether triggered by an agent `etch`, a streaming `pulse` settlement, or a human saving a file in Obsidian—passes through the atomic pre-commit pipeline:

```plaintext
[Candidate Delta] ──► 1. Parse Frontmatter & Resolve [[guard-<crest>]]
                                   │
                                   ▼
                      2. Verify proof: cert:smt:<hash> matches Wasm bytes & @realm seal
                                   │
                                   ▼
                      3. Execute guard(pre_doc, post_doc, wal_lines) in pure Wasm sandbox
                                   │
                         ┌─────────┴─────────┐
                         ▼ (false / trap)    ▼ (true)
              [Reject & Emit fault]     4. Check double-entry parity (∑ shift == 0)
                                                    │
                                                    ▼
                                         5. Sign ed25519 seal & commit to Git HEAD
```

## 3. Mandatory Streaming A2UI Ports (`view`)

### 3.1 Every Node Projects a Living User Interface

In conky v2.0, every document has a mandatory `view: "[[view-<crest>]]"` port. Whether a node is an autonomous strategist (`@standkeeper`), a double-entry ledger (`@wal`), a DuckDB P&L notebook (`@pnl`), a hardware sensor (`@pitcher`), or a multi-agent workspace (`@space-ops`), it exposes a declarative A2UI (Agent-to-User Interface) document.

- **Multi-Client Native Rendering:** The Obsidian conky plugin, mobile `voice` apps, and web dashboards subscribe to `[[view-<crest>]]`'s `pulse` stream and render native platform widgets with zero per-node frontend code.

### 3.2 Agent-Authored UI Evolution & Owner `gate` Approval

## 4. Natively Streaming Mesh Architecture (`pulse`)

### 4.1 Streaming Everywhere Without Breaking Git or 4KB Bounds

A naive Git-backed architecture suffers from disk thrash during high-frequency streams (e.g., a weight sensor streaming at 20Hz or an LLM streaming 80 tokens/sec). conky v2.0 solves this by separating **Ephemeral `pulse` Streams** from **Durable `seal` Checkpoints**:

```plaintext
Sensor / LLM / DuckDB Stream
  │
  ├─► t=0ms   pulse #1 (delta: oz=110.2) ──► blake3_1 ──► pushes to ![[slots]] & A2UI [[view]]
  ├─► t=50ms  pulse #2 (delta: oz=105.8) ──► blake3_2 ──► pushes to ![[slots]] & A2UI [[view]]
  ├─► t=100ms pulse #3 (delta: oz=100.0) ──► blake3_3 ──► pushes to ![[slots]] & A2UI [[view]]
  │
  ▼ [Quiescence Trigger: pour stabilized for 500ms]
[Pre-Commit guard Execution] ──► [ed25519 Git seal Commit referencing blake3_1..3]
```

### 4.2 Four Native Streaming Pathways

1. **Reactive `![[slot]]` Transclusions:** Transclusions in Markdown bodies (`![[wal#vaults]]`, `![[pnl#today_table]]`) are compiled by conky-airlock into live reactive subscriptions. When `@wal` emits a `pulse`, only the transcluded slice in downstream documents updates—keeping every host surface ≤4KB while propagating changes in <5ms.
2. **Incremental DuckDB Streaming (`organ/duckdb`):** SQL queries declared in a DuckDB notebook's frontmatter execute incrementally over incoming WAL Arrow/Parquet micro-batches, streaming updated Markdown table rows and A2UI sparkline deltas to `[[view-pnl]]`.
3. **Token-by-Token `mind` breath Streaming:** While `@standkeeper` reasons (`inhale` → `attend` → `act` → `exhale`), thought tokens and `shadow` simulation outcomes stream directly to `[[view-standkeeper]]` in real time, then coalesce into a single `seal` commit on `exhale`.
4. **Cycle-Safe Reactive Propagation:** The `pulse` router maintains a per-wave visited set and monotonic depth counter (`max_depth: 12`). If a diamond or cyclical transclusion graph (`A -> B -> C -> A`) attempts to re-enter an already-visited `(crest, field)` within the same causal wave, the router damps the echo (`fault::cycle` logged if divergent, or idempotent fixed-point convergence if identical).

pub enum GuardError {
    MissingGuard,
    ImpureImport(String),
    UnboundedLoop,
    WeakensRealmWard { counterexample: String },
    InvalidProofHash,
    ValidationFailed(String),
}

    wasm_engine: Engine,
}

                counterexample: cex,
