# Contributing

conky is early software. Small, focused contributions are welcome. Read [CLAUDE.md](CLAUDE.md) first: its rules apply to people and agents alike.

## Setup

- Python 3.11 or newer, Git, and `ssh-keygen` (the tests need both Git and `ssh-keygen`).
- Install with `pip install -e '.[dev]'`.
- Enable the pre-push hook once: `git config core.hooksPath scripts/hooks`.

## Checks

Run all checks with:

```bash
scripts/check
```

The pre-push hook runs the same command and blocks the push if it fails. CI runs the same command on every pull request and on pushes to `main`.

`scripts/check` runs six things: `ruff check`, `ruff format --check`, the tests, `scripts/check_docs.py`, the prose check described below and `scripts/check_commits.py`. Ruff selects the rule sets E, F, I, B, UP and SIM with a line length of 100. The pre-push hook is local configuration and is not cloned with the repository, so each clone enables it once with the command above.

## Prose

Published Markdown is linted with [Vale](https://vale.sh), which `pip install -e '.[dev]'` installs. The house style is in `.vale/styles/conky/`. Errors fail `scripts/check`: stock phrases and hype words, first person plural, em and en dashes, exclamation marks and rhetorical questions. Warnings and suggestions cover hedges, "there is" openers, "not only ... but" constructions and sentences over 35 words. They are reported, and you read them and decide.

- `scripts/check` runs `vale --minAlertLevel=error` on the README, CONTRIBUTING, CHANGELOG, SECURITY, CLAUDE.md and `docs/`.
- `vale .` reports every level.

## Commits

Subjects are `<type>: <summary>` with type one of feat, fix, docs, test, refactor or chore. The summary starts lower-case, has no trailing full stop, and the whole subject is at most 72 characters.

## Picking work

Take the step marked `next` in [docs/project/roadmap.md](docs/project/roadmap.md). Each step has a stable id and a state of `done`, `next` or `later`, and exactly one step is `next`; `scripts/check_docs.py` checks it.

## What a change must include

The pull request template's Done when list:

- `scripts/check` passes.
- Docs updated in the same change.
- A decision recorded if the design changed.
- Status and roadmap updated.
- A changelog line added if behaviour changed. The changelog follows Keep a Changelog and has an `## [Unreleased]` heading.

Every new invariant comes with a test that fails without it. Label stubs honestly: name them `stub` and say so in the doc comment.

## Figures

The figures under `docs/assets/figures/` are generated by the maintainers and committed as SVG; do not edit them by hand. To propose a new or changed figure, describe it in an issue or pull request.
